# 项目需求池

## 使用方式

- 本文档记录值得保留、但尚未进入开发计划的产品需求。
- `待讨论`：方向已提出，仍需澄清价值或范围。
- `待评估`：目标和基本方案已明确，尚未形成可执行实现计划或排期。
- `已规划`：已经形成可执行方案，可以进入实现。
- `暂缓`：当前不做，但保留重新评估的可能。
- `P0`：修正与核心目标冲突的现有行为，或打通当前最高频的关键闭环。
- `P1`：增强已经成立的核心流程，在 P0 稳定后推进。
- `P2`：有明确价值但范围较大，等待前置流程稳定或真实使用验证。
- 需求进入开发前，必须说明它如何帮助“内容内化”或“写作能力提升”。

## 当前规划边界

- Memos 与 Todo List 服务于快速记录和任务管理，不属于本项目“内容内化与写作提升”的当前主线。
- 当前项目不新增 `_memos` 内容类型，也不推进 Memos 浏览器扩展方案。
- 如果未来需要浏览器入口，只围绕待读、今日日记或选题等现有主线重新评估，不沿用旧 Memos 方案。

## WR-001 文章写作复盘

**优先级：P2** — 需要先有稳定的文章写作流程和足够复盘样本，再验证长期价值。

### 背景

用户希望通过持续写作提升表达能力。现有编辑器能够完成文章写作和发布，但缺少“确定训练目标、获得反馈、主动修改、沉淀经验”的复盘闭环。

### 目标

在文章编辑器内提供一个私人写作复盘流程，帮助用户发现具体表达问题，并通过自己修改文章形成可持续积累的写作经验。

### 候选交互

1. 在文章编辑器中通过单一“复盘”入口打开右侧抽屉。
2. 记录本次训练目标、核心表达和自我判断。
3. 第一阶段支持手动填写修改记录与下次注意事项。
4. 后续可增加 AI 反馈：引用具体段落，指出最重要的问题并提出追问，但不自动重写正文。
5. 复盘内容与公开文章分离，保存为私人 Markdown 侧车文件。

### 非目标

- 不做通用 AI 聊天页面。
- 不做一键全文润色或自动改写。
- 不强制所有日记进入复盘流程。
- 不公开展示私人复盘内容。

### 关键原则

- AI 的角色是指出盲点和促进修改，不是代替用户写作。
- 每次复盘优先聚焦一个训练目标。
- AI 不可用时，手动复盘仍可独立完成。
- 是否进入开发，以用户真实写作过程中是否持续需要复盘为判断依据。

### 待确认

- 第一版是否只支持正式文章。
- 私人复盘文件的最终目录和命名规则。
- 是否需要展示文章修改前后的差异。
- 何时将需求从“待评估”升级为“已规划”。

## WR-002 Markdown 所见即所得编辑器

**优先级：P2** — 当前 Markdown 编辑器已完成工具栏与预览基础闭环，待通过真实写作频率验证是否需要替换编辑内核。

### 背景

文章编辑器的工具栏已经支持标题、强调、高亮、待办、表格和引用等格式操作，但正文仍以原始 Markdown 输入。用户在写作时需要在编辑态和预览态之间切换，格式标记也会干扰连续写作体验。

### 目标

在保持 Markdown 为唯一存储格式及现有图片路径规则不变的前提下，提供所见即所得的写作画布：标题、列表、待办、表格、高亮、图片、代码和内部引用在输入时直接排版显示。

### 关键约束

- 既有 Markdown 文章必须可无损打开、编辑和保存。
- 图片继续存储在 `source/images/YYYY/MM/...`，写回路径必须为 `/Alpaca-Notes-CMS/images/...`。
- 编辑器与 Markdown 的转换必须覆盖嵌套列表、代码块、表格、引用和内部链接。
- 不将项目改造为重型 CMS，不改变 GitHub 仓库作为内容源的模式。

### 待评估

- 采用成熟编辑器并序列化为 Markdown，或零依赖实现轻量编辑层。
- 首期支持的 Markdown 格式范围及降级策略。
- 是否先通过写作行为数据确认预览切换成本，再进入实现。

## KN-001 划线转化为自己的知识

**优先级：P0** — 当前“划线直接成为知识点”的行为与已确认的内容内化原则冲突，应优先修正。

### 背景

当前项目会把用户选中的原文直接保存为知识点，知识点标题和正文都主要来自原文。这会把“摘录”误认为“自己的知识”，与项目帮助用户内化内容的目标冲突。

### 目标

将划线与知识点明确分开：划线首先作为原文摘录保留，只有在用户用自己的话完成理解和重新表述后，才能转化为知识点。

### 候选交互

1. 用户在待读、文章或日记预览中选择文字，先保存为划线或批注。
2. 用户主动点击“转为知识”。
3. 打开知识草稿面板，自动带入不可编辑的原文摘录和来源。
4. 用户必须填写“我的理解”；“为什么重要”和“可以用在哪里”为可选内容。
5. 知识点标题根据“我的理解”生成，不再直接截取原文。
6. 保存后，知识点保留原文、来源文档和外部链接的回链。

### 非目标

- 不把每一条划线自动生成知识点。
- 不让 AI 在用户没有表达自己理解时自动代写知识点。
- 不删除或替代现有划线、批注和局部评论能力。

### 关键原则

- 原文划线只是素材，不是知识点。
- 用户自己的重新表述是创建知识点的必要条件。
- 普通感想可以只保留为局部评论，不强制升级为知识点。
- 只有具有独立含义和复用价值的认知才进入知识库。

### 待确认

- “知识草稿”采用临时面板还是直接打开未保存的知识点编辑器。
- 第一版是否只要求填写“我的理解”，其余字段后续再增加。
- 是否允许从已有批注卡片再次发起“转为知识”。

## DR-001 高亮评论引用到今日日记

**优先级：P0** — 直接打通现有高亮评论与每天持续记录日记的高频流程，改动价值明确。

### 背景

用户会在待读正文中划线，并在右侧高亮卡片中记录局部评论。当一段内容触发值得记录的想法时，用户希望将原文、评论和来源带入当天日记，继续写下当天的感受和经历。

当前日记按时间戳创建，同一天可以生成多篇。用户的真实习惯是每天维护一篇日记，持续追加当天值得记录的事情和想法。

### 目标

打通“待读高亮与评论 → 今日日记”的流转，并将日记创建规则收敛为一天一篇，减少复制粘贴和重复日记。

### 候选交互

1. 在待读右侧高亮卡片提供“引用到今日日记”操作。
2. 引用内容包含原文摘录、用户评论、原待读标题和来源回链。
3. 如果今日日记不存在，自动创建；如果已经存在，追加到现有日记正文末尾。
4. 每条引用以当前时间作为小标题，引用后留出继续书写个人感受的位置。
5. 保存成功后继续停留在待读页面，并提供“打开今日日记”的轻量入口。
6. 用户主动新建日记时，如果今日日记已经存在，直接打开而不重复创建。

### 建议写入格式

```markdown
## 14:32

> 原文摘录

我的评论：用户在高亮卡片中填写的评论。

来源：[[原待读文章标题]]
```

### 非目标

- 不自动把所有高亮同步到日记。
- 不改变历史日记文件或自动合并同一天已有的多篇日记。
- 不在引用后强制跳离当前待读页面。
- 不把日记变成严格的结构化表单。

### 关键原则

- 日记以“一天一篇、持续追加”为默认组织方式。
- 引用必须同时保留原文、用户评论和来源，避免脱离语境。
- 引用到日记由用户主动触发，不制造自动化噪音。
- 日记中的引用保存独立副本，原待读后续变化不破坏已有日记。

### 待确认

- 来源回链采用现有内部引用语法还是增加精确到高亮的锚点。
- 追加内容前是否需要检测同一高亮已被引用，避免重复写入。
- 第一版是否需要在日记中提供返回原高亮的操作。

## TP-001 独立选题库与文章转化

**优先级：P1** — 是从零散素材进入写作的重要桥梁，但涉及新的独立内容对象和素材关系，应在 P0 流程稳定后推进。

### 背景

用户通常在产生一个想表达的主题后才开始写文章。选题最初往往只有一两句话，灵感可能来自视频、情绪、书籍、待读、日记或知识点。把这种轻量灵感直接放进文章列表，会让文章列表充满尚未准备写作的短记录，也不符合用户对文章的理解。

因此，选题不应只是文章的一种状态，而应作为独立的轻量内容对象存在；只有用户明确决定“开始写作”时，才创建文章草稿。

### 目标

提供一个独立选题库，用很低的成本记录写作灵感、核心表达和关联素材，并在选题成熟后顺畅地创建、关联文章草稿。

### 选题内容

- 选题标题。
- 一两句话的核心想法或“我想表达什么”。
- 灵感来源。
- 关联的待读高亮、日记片段、书籍批注和知识点。
- 当前状态。
- 由该选题创建的文章链接。

### 候选交互

1. 用户在独立的选题库中快速记录标题和一两句话。
2. 用户可从待读高亮、日记片段、书籍批注和知识点执行“加入选题素材”。
3. 选题详情展示已关联素材，但不要求提前撰写文章正文。
4. 用户点击“开始写作”后创建新的文章草稿。
5. 新文章自动带入选题标题和核心想法，并在右侧素材栏展示该选题已有素材。
6. 文章与选题保持双向关联；创建文章后选题继续保留。

### 状态建议

```text
待展开 → 素材收集中 → 已开始写作 → 已完成 / 已搁置
```

### 非目标

- 不把选题混入现有文章列表。
- 不把每条灵感立即创建成文章 Markdown。
- 不要求一个选题刚创建时就有完整提纲。
- 不在第一版建设复杂的选题推荐、评分或排期系统。

### 关键原则

- 选题是轻量写作灵感，文章是决定正式展开后的长内容，两者是不同对象。
- 选题可以独立存在，不因文章被删除而丢失。
- 素材优先关联选题，创建文章后由文章继续访问同一批素材。
- 用户主动点击“开始写作”才发生选题到文章的转化。

### 已否决方案

- 不采用“选题、写作中、已发布都是同一个文章对象的不同状态”方案，因为用户不希望只有一两句话的选题出现在文章列表中。

### 待确认

- 选题在界面中的入口位置和展现形式。
- 选题数据使用独立 Markdown 文件还是轻量索引文件。
- 第一版是否限制一个选题只关联一篇文章。
- 文章完成后，选题状态是否自动更新为“已完成”。

## RL-001 自主总结与 AI 校验

**优先级：P1** — 能增强全文理解，但依赖 AI 校验设计，且现有手动总结已经可用，不阻塞当前主流程。

### 背景

用户希望通过全文总结检验自己是否真正理解了读到的内容。若由 AI 先生成摘要，用户容易跳过主动回忆和重新组织，无法有效完成内容内化。

现有待读结构已经包含“我的总结”，可以在此基础上增加总结校验，而无需新增内容类型。

### 目标

鼓励用户先用自己的语言完成全文总结，再由 AI 对照原文检查遗漏、误解和表达结构，帮助用户修正理解但不替代用户思考。

### 候选交互

1. 用户阅读完成后，在现有“我的总结”字段中自行撰写总结。
2. 用户主动点击“检查总结”。
3. 系统将原文与用户总结交给 AI 对照分析。
4. AI 反馈用户是否抓住核心观点、遗漏了哪些关键内容、是否存在误解，以及哪些表达不够清楚。
5. AI 通过问题或修改方向引导用户自己完善总结，不直接覆盖原总结。
6. 用户修改后可再次检查，但不强制达到评分或通过状态。

### 非目标

- 不让 AI 在用户动笔前先生成全文摘要。
- 不一键替换或改写“我的总结”。
- 不用统一分数衡量不同类型文章的理解质量。
- 不强制每篇待读都完成总结或 AI 校验。

### 关键原则

- 用户先主动回忆和重新组织，AI 后提供校验。
- AI 反馈必须区分“遗漏”“误解”和“表达不清”。
- 用户总结始终是内容主体，AI 输出只是临时反馈或辅助记录。
- AI 不可用时，原有手动总结流程不受影响。

### 待确认

- AI 校验反馈是否需要随待读长期保存。
- 第一版反馈采用问题列表还是按“核心观点、遗漏、误解、表达”分区展示。
- 将阅读状态改为“已读”时是否只做轻量提示，不强制打开总结。

## AN-001 批注处理中心

**优先级：P2** — 已有批注聚合页面可满足当前查看需求，集中处理动作有价值但不阻塞主流程。

### 目标

在现有批注管理页面集中处理待读和书籍批注，减少逐篇返回原文的操作成本。

### 候选交互

- 从批注卡片转化为自己的知识。
- 将批注和评论引用到今日日记。
- 将批注加入选题素材。
- 标记批注已处理。

### 关键原则

- 复用现有批注聚合页面，不新增顶层模块。
- 所有转化操作由用户主动触发。
- 批注处理中心只聚合操作，不改变原始批注的事实来源。

## WF-001 自动识别内容内化进度

**优先级：P2** — 用于改善长期回顾和筛选，但当前先保证总结、知识、日记和选题的转化链路成立。

### 目标

在“未读、阅读中、已读”之外，让用户看见一篇内容是否已经被总结、批注、沉淀或用于写作。

### 候选状态

- 已总结。
- 有批注。
- 已转化知识。
- 已引用日记。
- 已用于选题。

### 关键原则

- 状态从现有内容和关联关系自动推导，不要求用户重复维护。
- “已读”和“已内化”保持不同含义。
- 第一版不设计综合分数或复杂进度条。

## KN-002 今日知识点再利用

**优先级：P2** — 项目已经具备今日知识点展示，后续只需增强再利用动作，不必新建知识回顾模块。

### 目标

让被重新展示的知识点能够再次进入思考、日记和写作，而不只是被动浏览。

### 候选交互

- 补充“我现在如何理解”。
- 引用到今日日记。
- 加入选题素材。
- 打开原始来源。

### 关键原则

- 复用现有今日知识点页面。
- 不新增打卡、积分或强制复习机制。
- 优先促进知识被再次表达和使用，而不是增加浏览次数。
